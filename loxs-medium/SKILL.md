# loxs-medium — processed article log

This is not where techniques live — it's an index. Run this exact pipeline every single time the hunter shares a new Medium article URL (via `/loxs-medium <url>` or by pasting a link and asking to process it). Don't skip steps or improvise a different flow — the point of writing it down here is so the process is identical every time.

## Step 1 — Check the log first

Before fetching anything, check the "Processed articles" table below for the URL. If it's already there, tell the hunter it's already been processed and point to the topic skill — don't reprocess.

## Step 2 — Fetch the article content

1. Try `WebFetch` on the URL first (fast path).
2. If `WebFetch` fails, errors, or returns clearly broken/empty content (paywall block, JS-rendered shell, bot check, etc.), fall back to Chrome browser automation: load the Chrome tools (ToolSearch for `mcp__claude-in-chrome__*` core set), open the URL in a new tab, and read the rendered page content from there instead.
3. Either way, extract: vulnerability class/root cause, the researcher's methodology (recon → exploitation steps), specific tools/payloads/requests shown, and impact/reporting details — same level of technical detail as previous entries in the topic skills (see `race-condition-testing` for the bar to match).

## Step 3 — Identify the topic and route it

1. Determine which vuln class / technique category the article is really about (e.g. race condition, IDOR, SSRF, XSS, auth bypass).
2. Check whether a topic skill already exists for that category:
   - **Exists** → add a new dated, numbered entry to that skill's "Recorded techniques" section, following the same structure as existing entries (Where / Root cause / Exploit steps / Impact framing / Generalize note). Don't duplicate or create a second skill for the same topic.
   - **Doesn't exist** → create a new topic skill directory under `~/.claude/skills/<topic-name>/SKILL.md`, mirroring the structure of `race-condition-testing` (frontmatter with a pushy trigger description, Core theory, Trigger technique, Recorded techniques).
3. Update `bughunting-workflow`'s "Linked technique skills" section: add a line naming the new/updated topic skill and which phase(s)/vuln class it applies to, if it isn't already listed there.

## Step 4 — Log it here

Append a row to the "Processed articles" table below (date, article title+link, topic skill it fed into). This is what step 1 checks on future runs — never skip it.
